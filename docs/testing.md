# Testing

| Command | What it runs |
| --- | --- |
| `pnpm test` | Vitest unit tests (no database) |
| `pnpm test:db` | Vitest database tests against the local test Postgres (port 54329, `scripts/test-db.sh`) |
| `pnpm test:e2e` | Playwright end-to-end tests against a production build on port 3100 |
| `pnpm db:reset` | Rebuild the test database from the migrations |

Playwright's `webServer` builds and starts the app, and `tests/e2e/global-setup.ts` resets the test
database and starts the Anthropic mock on port 3199. Let Playwright start the server: a server started
by hand keeps pooled connections to a database that the next run resets, and it fails with
"Something went wrong".

Never call the real Anthropic API from the regular suite. Claude is always the mock there.

## The v1.0 acceptance test (spec 13.1)

`tests/e2e/acceptance.spec.ts` is one test that walks all eleven steps of the minimum acceptance
scenario in order, each as a named `test.step`:

1. Create a session.
2. Paste a README.
3. Select a previously uploaded universal script (uploaded to the library first, as setup).
4. Ask Claude to adapt it.
5. Review the requirements matrix and the proposed code changes.
6. Save the approved adaptation and download it (the downloaded bytes must equal the saved content).
7. Upload LEADS results (the score is recorded).
8. Ask Claude for a remediation proposal.
9. Review it and download the follow-up script.
10. Upload verification evidence and complete the flowchart (the completion, submit-final and forensic rules apply as implemented).
11. Sign out, sign in, reopen the session, and check that every document, version, note and status is intact.

At every step the test also checks privacy: an anonymous visitor's `/p` search must find none of the
session's distinctive strings, and the session's private routes must refuse the visitor. The final
assertion repeats this for strings from the README, the script, the report and the notes. The probe is
not vacuous: a control paste that the test publishes on purpose must be found by the same search.

Fixtures live in `tests/fixtures/acceptance/`. The universal script has a UTF-8 BOM and CRLF line
endings, so it is generated by `tests/fixtures/make-fixtures.ts` (run `pnpm fixtures`)
and committed.

### Mock mode (default, runs in `pnpm test:e2e` and in CI)

Claude's answers come from `tests/e2e/claude-mock.ts`, which queues deterministic responses on the
shared mock (`tests/support/anthropic-mock.ts`). They are valid for the app's zod schemas, so the
test asserts exact requirements, verdicts, diffs, flags and notes. Run it alone with:

```sh
pnpm exec playwright test tests/e2e/acceptance.spec.ts
```

### Real mode (nightly)

`.github/workflows/nightly.yml` runs the same spec against the real Claude API every night and on
demand (`workflow_dispatch`, with an optional model). The mock is not queued, and the assertions that
depend on Claude's wording become structural: rows exist and are Proposed, every high-impact flag can
be acknowledged, the editor shows the stored script, and downloads still
equal the saved content byte for byte. Everything else, including every privacy check, is unchanged.

| Variable | Meaning |
| --- | --- |
| `ACCEPTANCE_REAL_CLAUDE=1` | Switch to real mode (read by the spec and by `playwright.config.ts`) |
| `ANTHROPIC_API_KEY` | Required in real mode; the config throws without it. In CI it comes from the repository secret of the same name, set in the `env:` of the single Playwright step only (not job-wide), so install and browser download never see it |
| `ACCEPTANCE_CLAUDE_MODEL` | Optional model override (sets `CLAUDE_MODEL` for the server) |
| `ACCEPTANCE_CLAUDE_TOOL_MAX_TOKENS` | Optional override of the per-call output budget (default 4096) |

The budget is set through the app's own knobs in `src/server/claude/client.ts`, which
`playwright.config.ts` fills in for real mode: `CLAUDE_TOOL_MAX_TOKENS=4096` (the app default is
16000), `CLAUDE_MAX_TOKENS=1024`, `CLAUDE_CONTEXT_TOKENS=20000` and `CLAUDE_MAX_RETRIES=2`. One run
makes three Claude calls (extract requirements, assess coverage, adapt) plus one for the remediation,
over a README of a few paragraphs and a script of a few dozen lines. The test timeout is 30 minutes
and each wait for Claude is up to 4 minutes. The workflow passes `--retries=0` so a failure never
spends the budget twice.

To try it locally, with your own key in the environment (never put it in a file):

```sh
ACCEPTANCE_REAL_CLAUDE=1 ANTHROPIC_API_KEY=... pnpm exec playwright test tests/e2e/acceptance.spec.ts --retries=0
```

Real mode costs money and can fail for reasons that are not regressions (an overloaded API, an
answer that no longer fits the schema). A failure means "read the artifact and decide", not
"revert the last commit".

## Shared e2e helpers

`tests/e2e/support/helpers.ts` holds the helpers that more than one spec uses (`signIn`, `newSession`,
`pasteReadme`, `createLibraryScript`, `openFlowchart`, the mock handle and the panel locators). Import
them rather than copying them into a spec.

## Known instability

`completion.spec.ts` "Add question" occasionally stalls (about one run in three under CPU stress).
It is a pre-existing flake and is unrelated to the acceptance test, which waits only on concrete UI
state and never on fixed sleeps.
